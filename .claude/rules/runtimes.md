# Agent runtimes — the second axis

Adding a whole new CLI: run the `adding-a-runtime` skill (procedure + gates);
`docs/adding-a-runtime.md` is its reference for the member-by-member contract.

## The invariant

**Agent runtime is a SECOND axis, orthogonal to transport** — a window runs Claude Code (default), Codex, or Grok, held in `WindowState.runtime` (default `"claude"` → zero state migration). Runtime is a window property, **never** in the binding string (`@<id>`/`docker:<agent>` stay transport-only, so `resolve_binding` is untouched). **Put runtime-specific behavior behind `runtimes.AgentRuntime`** (`launch_command`/`iter_transcripts`/`parse_entries`/`exit_command`/`latest_context_tokens`/`is_working`/`has_queued_input`/`panel_actions`/`is_edit_tool`+`diff_header_re` for `/diff`/`native_image_input` for image input/`pane_alive_commands` for the dead-window health check (codex's foreground is `codex`, not `claude`/`node` — a hardcoded claude set reaped every codex window 30 s after launch)/`list_sessions`+`picker_icon` for the session picker's agent menu/`history_transcript` for `/commands` history/`interrupt_keys` for `/esc` (codex: Escape only — an idle Ctrl-C arms its TUI quit)), NOT `if codex:` at call sites. **Window-bootstrap divergence is CAPABILITIES, never `rt.name != "claude"` comparisons** — `uses_session_map` (hook wait + hook-missing alarm + cwd persistence + load_session_map's stale-window sweep; the shared stamp is `session_manager.tag_window_runtime`), `auto_forward_first_message` (codex False: a fresh codex can open on its sign-in menu), `ready_message_key`, `is_available` (`pickable_runtimes()` offers only installed CLIs — no codex binary ⇒ no Codex tab ⇒ no dead window typing a missing command); a name comparison silently mis-treats a third runtime as codex-like. Topics remember their runtime (`thread_runtime_memory`, recorded by `record_thread_directory(..., runtime=)`) so the memory rebind after a window death relaunches the SAME CLI — `_auto_bind_to_directory` resolves remembered → `default_runtime()` (`CCBOT_DEFAULT_RUNTIME`, availability-checked), never hardcodes claude. Hookless runtimes resolve transcripts by cwd «newest wins», so **two live codex windows on one directory would cross-talk** — creation paths refuse the second via `session_manager.has_live_agent_on_cwd` (i18n `bot.same_dir_conflict`); the capped rollout scan has a sticky last-resolved fallback so a quiet window doesn't go dark when its rollout leaves the newest-60 — the monitor iterates runtimes and calls the interface (`_process_transcript` is the shared read→parse→emit tail); a third model = one subclass, no monitor rewrite.

## Codex

Non-obvious codex bits (all behind the runtime): it has **no SessionStart-hook session_map** (the hook doesn't fire on interactive launch in 0.144.x), so the monitor resolves a codex window's rollout (`~/.codex/sessions/**/rollout-*.jsonl`) by matching `session_meta.cwd` to `WindowState.cwd` (newest wins) and mirrors the rollout's session id onto the window; launch is bare `codex` (no `--name`; resume = `codex resume <id>`; exit = `/quit`; opt-in `CODEX_BYPASS_SANDBOX=true` appends `--dangerously-bypass-approvals-and-sandbox` — a **last resort only** (OpenAI doesn't recommend it for personal machines; it's `danger-full-access`). If codex's sandbox can't init (`bwrap: setting up uid map: Permission denied` on Ubuntu 24.04 — AppArmor's `bwrap-userns-restrict` only covers `/usr/bin/bwrap`, codex uses its bundled bwrap), the PROPER fix is `apt install bubblewrap` (+ the AppArmor extra-profile), an infra/admin task that keeps codex sandboxed; only then can codex run shell / edit files / read documents. Images work regardless of the sandbox — see below); inbound images use codex's **native composer** (`native_image_input`): `session_manager.send_composer_image` types the path so codex attaches it as `[Image #N]` (a CLIENT-side read that bypasses the sandbox), NOT the `(image attached: <path>)` text marker (Claude's way, which codex's sandbox can't open); documents still use the text marker + shell read (so they need `CODEX_BYPASS_SANDBOX` or a working sandbox); its sign-in menu / device-code / onboarding screens reuse the **interactive-UI** (photo + ↑↓⏎ nav + auth-URL surfacing) via a provider-agnostic **`is_login` flag** on `terminal_parser` UI patterns (+`parse_login_code` for the copyable one-time code) — Claude's `/login` uses the same path, so **don't build codex-specific login handling**. Busy-detection is runtime-aware: codex has **no `─` chrome separator**, so `is_claude_working` can't anchor — `CodexRuntime.is_working` matches codex's `(Ns • esc to interrupt)` counter (`is_codex_working`) and `has_queued_input` matches its "Messages to be submitted after next tool call" hint. Call sites (restart-guard, `/inject` busy-gate, task-pin idle, reaction-confirm/ack) go through the **`session_manager.is_agent_working`/`agent_has_queued_input`** wrappers (dispatch on `WindowState.runtime` via `window_runtime()`), never `is_claude_working` directly. Codex's approval / pick-an-option menus are caught by a **generic `ChoiceMenu`** UI pattern (cursor on a numbered option `› N.`/`❯ N.` + a confirm/cancel footer) — provider-agnostic, so any new agent's numbered menu surfaces via the same photo+nav path with no new pattern; it's LAST in `UI_PATTERNS` so named patterns (AskUserQuestion's text-surfacing) win first.

## Grok

Non-obvious Grok bits (`GrokRuntime`, probed live on 0.2.111 — full detail in its docstring): hookless like codex, but resolution is direct — grok's own `~/.grok/active_sessions.json` (live-pid registry) names the cwd's live session, falling back to the newest session dir in `~/.grok/sessions/<url-encoded-cwd>/` (groups matched by DECODING names, so grok's encoder never needs reproducing); the monitored file is **`updates.jsonl` — NEVER "simplify" to the flatter `chat_history.jsonl`**: `/compact` rewrites that one in place, which breaks byte-offset incremental reads (updates.jsonl stays append-only through compaction). Grok's Claude-compat scan **does run `~/.claude/settings.json` hooks incl. `ccbot hook`** — harmless only because grok's stdin payload is camelCase (`sessionId`) and hook.py reads snake_case; don't "fix" hook.py to accept camelCase, that would let grok sessions pollute `session_map.json`. Its tool-approval prompt is radio-style (`1 (●)` — no cursor glyph, so `ChoiceMenu` can't match → own `GrokApproval` pattern, driven by the standard ↑↓⏎ keyboard) and its **preselected option is «Yes, and don't ask again» = always-approve** — so blind confirms route through `UIPattern.confirm_keys` (GrokApproval: Down→«Yes, proceed»→Enter; 👍-to-confirm consumes it via `decide_confirm_action`); a manual ⏎ on the photo keyboard still accepts the preselect, which the photo shows. No `/diff` (grok draws edit diffs colour-only, no ± gutter for the shared crop engine); `/mcps` not `/mcp` (`panel_slash_commands` override); welcome screen has a LIVE composer → `auto_forward_first_message=True` (unlike codex).
